# 中期答辩与投稿执行蓝图

## 0. 项目定位

**论文题目（暂保持不变）**：面向非连续时间约束的区块链数据共享关键技术研究及实现。

本项目以完成专业硕士毕业要求为优先。研究不宣称已经提出并证明一套新的 CP-ABE 密码体制；中期阶段的可交付成果是一个可复现的工程原型，以及对其时间策略表达和撤销性能的可信测量。

### 0.1 中期阶段可主张的贡献

1. 设计并实现非连续时间访问策略的编译器：将离散时刻或时间区间转换为紧凑的层次化时间节点集合。
2. 实现链上状态驱动的版本化撤销原型：撤销只更新访问状态、密文头部或其索引，不重加密文件数据体。
3. 实现 KEM/DEM 风格的数据体和控制头部分离：文件数据体采用标准 AES-GCM；访问控制元数据、状态版本和完整性哈希独立管理。
4. 建立可复现实验平台：比较基线枚举策略、区间合并策略与层次化策略编译，并测量策略规模、编译时间、头部更新时延和模拟链上开销。

### 0.2 必须避免的表述

- 不将原型中的策略封装称为“已被严格证明安全的新 CP-ABE”。
- 不将区块哈希绑定直接称为“前向安全”，除非后续完成明确的安全游戏和归约证明。
- 不声称撤销能阻止已经获得明文或旧数据体副本的用户；撤销只约束新状态下的访问与密钥头部获取。
- 不把 Python 模拟账本的运行时间写成真实公链 Gas 结果。

## 1. 研究范围与问题

### 主研究问题

在公开文件集的加密数据共享场景中，层次化时间策略编译与状态版本化撤销，能否在不重加密数据体的条件下，降低非连续细粒度时间策略的表达规模和撤销处理开销？

### 三个子问题

1. 当允许访问时间由大量离散、非连续的分钟级时间点组成时，层次化策略编译相对逐时刻枚举能减少多少策略节点与元数据字节数？
2. 在不同策略复杂度下，策略编译、加密数据头生成和合法用户访问的端到端时延如何变化？
3. 在不同文件大小与类型下，版本化撤销仅更新元数据头部时，数据体重加密基线与头部更新方案的时间、I/O 与模拟链上存储开销差异如何变化？

### 暂时排除项

- 完整的 DBDH/DLIN 安全规约和归约证明。
- 在智能合约中保存主密钥、执行配对运算或生成真正的私钥陷门。
- 医疗、政务等真实敏感数据处理和伦理审批。
- 对“所有区块链 ABE 方案”的全面比较；仅选择可复现的 1--2 个基线。

## 2. Python 最小可行原型（MVP）

### 模块边界

```text
输入时间策略 + 文件
  -> policy_compiler       生成枚举/区间/层次化策略表示
  -> data_crypto          AES-GCM 加密文件数据体
  -> header_manager       生成含策略摘要、版本号、哈希的密文头部
  -> state_ledger         登记 FileID、header hash、epoch、撤销名单
  -> access_service       校验用户、时间策略与最新 epoch 后返回访问结果
  -> benchmark            固定随机种子，导出 CSV、图与运行日志
```

### 技术选择

- Python 3.11；`cryptography` 实现 AES-GCM；`pytest` 做单元测试；`pandas`、`matplotlib`、`seaborn` 做结果整理和绘图。
- 第一阶段使用 Python 状态账本；第二阶段用 `eth-tester` + `web3.py` 模拟本地 Ethereum 链。`eth-tester` 支持 Python 本地测试账户、出块和时间推进，适合论文原型验证，但不等同于生产链。[eth-tester](https://github.com/ethereum/eth-tester)
- 智能合约只管理 `FileID -> header hash / epoch / revoked user hash` 等状态；密钥与文件明文永不上链。

### 最小目录


## 3. 实验设计

### 数据集与文件样本

实验的因变量是加密、策略与撤销性能，数据内容本身不参与模型训练，因此公开数据集主要提供真实的文件大小和格式分布。

- 开发期：合成文件集，覆盖 4 KB、64 KB、1 MB、10 MB、100 MB，且每种大小固定随机种子生成。
- 验证期：从 GovDocs1 的学生友好子集抽取文件。该语料提供多类型、可自由再分发文件，且官方提供每个约 1,000 个文档的子集，适合本机试验。[GovDocs1](https://digitalcorpora.org/corpora/file-corpora/files/)
- 文本补充：可选用 CMU 发布的 Enron 邮件数据子集，只用其文件大小与文本格式分布，不分析邮件语义。[CMU Enron Dataset](https://www.cs.cmu.edu/~enron/)

所有实验记录文件哈希、大小、MIME/扩展名、抽样种子和版本；论文只报告聚合统计，不展示数据内容。

### 基线与对照

| 编号 | 方案 | 目的 |
|---|---|---|
| B0 | 逐分钟枚举时间点 | 代表细粒度策略的直接表达 |
| B1 | 合并连续区间 | 代表不使用层次树的常规压缩 |
| P1 | 层次化时间节点编译 | 本文原型策略表达 |
| R0 | 撤销后重加密数据体与头部 | 撤销成本基线 |
| R1 | 仅更新头部与状态 epoch | 本文原型撤销路径 |

### 核心指标

1. 策略节点数、序列化字节数、编译时间。
2. 数据体加密时间、头部生成时间、访问校验时间、峰值内存。
3. 撤销端到端时延、更新字节数、磁盘 I/O 字节数、版本同步成功率。
4. 本地链阶段：交易数、合约状态写入字节数、`eth-tester` 估算/记录的执行结果。不得把它写成主网 Gas。

### 实验规范

- 每个配置至少重复 20 次，记录均值、中位数、标准差和 95% 置信区间。
- 预先固定硬件、Python 版本、依赖版本、随机种子、数据清单和命令行参数。
- 若原型失败、性能无优势或策略规模未下降，保留原始日志并如实报告；不挑选“好看”的运行结果。

## 6. 投稿策略

不把“已投稿”当作中期前置条件。中期先展示可复现原型和初步实验；当至少完成完整实验、对照分析和真实引用核验后再投稿。

- 冲刺目标：《软件学报》要求原创、完整且有充分比较的工作，适合作为后续成熟版本的上限，而非当前保底路径。[投稿指南](https://jos.org.cn/jos/ch/reader/view_fixed_content.aspx?id=instructions)
- 保底路径：待导师或学院确认毕业认定口径后，按“信息安全/区块链/软件工程方向、可接受工程原型与实验评估”的期刊或会议重新筛选。筛选时必须核实：收录、投稿截止、审稿周期、版面要求、是否接受在审稿件。
- 一稿只投一个正式渠道；中期材料中“拟投稿”与“已投稿”严格区分。

## 7. 中期答辩的诚实口径

可以说："当前已完成策略编译和版本化撤销原型的第一阶段，实现了可复现实验闭环；下一阶段将扩展本地链仿真、公开文件集实验和形式化安全分析。"

不要说："本方案已严格证明 IND-CPA 安全、已实现 O(1) 撤销、已获得主网 Gas 优势。" 除非相应证明、实验定义与原始结果均已完成。
