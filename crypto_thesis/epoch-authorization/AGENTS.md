# Project Operating Rules

This repository supports the professional master's thesis **"面向非连续时间约束的区块链数据共享关键技术研究及实现"**. This file is the entry point for persistent project context and operating constraints. Chat history is not the primary source of project facts.

Before any task, read `docs/project-governance/00-PROJECT-CONSTITUTION.md`, `01-CURRENT-STATE.md`, `06-RISK-AND-HARD-STOPS.md`, and `07-NEXT-ACTION.md`, then check the current Git HEAD and worktree. Facts are ranked as: repository evidence and code; latest frozen governance decision; current user instruction; historical design documents; chat memory.

Do not silently change the thesis title, the three research-content sequence, or the current method positioning. Do not present plans as results, invent data, bypass an active hard stop, or treat PILOT_ONLY data as formal performance evidence. Record material design changes in `02-DECISION-LOG.md`, completed experiments in `05-EXPERIMENT-REGISTRY.md`, and thesis claims in `04-CLAIM-EVIDENCE-MATRIX.md`. Update current state and next action at task completion.

Never commit private keys, passwords, secret files, or private directories. Do not push. Do not collect formal performance data unless the governance records explicitly admit it.
