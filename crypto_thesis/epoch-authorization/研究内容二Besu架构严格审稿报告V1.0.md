# 研究内容二 Besu 架构严格审稿报告 V1.0

## 致命问题

无。未发现秘密上链、Epoch 被当作物理时间或以单机环境冒充多组织部署的设计。

## 重大问题

| 编号 | 问题 | 风险 | 处理要求 |
|---|---|---|---|
| M1 | `updatedAtBlock` 被用作资源状态版本 | 同一区块多笔状态交易可能共享版本，旧 CAP2 无法可靠失效 | 增加每次授权相关迁移均递增的 `stateVersion` |
| M2 | Besu 账户默认不解锁 | Web3 `transact` 无法用于真实节点 | 增加客户端本地签名与原始交易提交 |
| M3 | QBFT `extraData` 超过以太坊普通块限制 | Web3.py 读取区块失败 | 注入 `ExtraDataToPOAMiddleware` |
| M4 | RPC 故障与发行竞态原先抛出系统异常 | 上层行为不统一 | 映射为 `SYSTEM_STATE_UNAVAILABLE` 并拒绝 |

## 一般问题

1. 当前角色由部署账户集中授予，适合受控原型，不足以代表生产治理。
2. Nonce 消费仍为链下原子存储，跨 Verifier 部署需要共享后端。
3. 确认深度默认为 0；QBFT 最终性环境可用，但正式多主机实验需冻结确认策略。
4. Docker 镜像拉取在本机出现摘要/短读错误，已使用官方发布包直接运行，compose 未作为已验证路径。

## 审稿结论

V1.0 附重大修改后通过。M1 至 M4 关闭前不得宣称链状态绑定闭合，也不得设计正式多主机性能实验。
