# 第5章答辩陈述稿

研究内容二关注动态授权状态如何在真实联盟链上形成可审计闭环。研究内容一已经给出唯一语义表示 \(I^*\) 和 `policyDigest`，本章通过 `AuthorizationState` 将资源、Epoch、策略版本和用户密钥版本锚定到五节点Besu QBFT链，并在CAP2中绑定 `chainId`、合约地址、资源状态和用户状态。

系统采用两个独立Verifier和PostgreSQL原子共享Nonce。并发50、100和500个相同能力请求均只有一次成功；RPC故障时Issuer停止签发，数据库故障时Verifier拒绝授权。这里的结论限定于冻结实现和故障模型，不表述为绝对安全。

V13正式实验重新预注册并完整重跑。实验包含108个因素配置、9720个运行块和77760条请求，主要推断以运行块为单位，避免请求级伪重复。四种方法的运行级中位时延约为196至199毫秒。逐请求三次真实链读取占端到端时延98.66%至98.80%，并发度是主要观测因素。热点提高缓存命中率，但缓存收益置信区间跨零，没有稳定工程收益；\(C(P)\) 也未表现出Baseline-I不可复制的优势。

因此，本章的核心贡献不是宣称某个派生结构更快，而是完成真实链状态、CAP2完整绑定、共享Nonce、多Verifier一致性和Fail-Closed的系统闭环，并通过负面结果明确方法边界。
