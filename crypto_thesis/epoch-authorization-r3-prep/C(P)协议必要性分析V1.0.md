# C(P) 协议必要性分析 V1.0

## 1. 审查对象

Baseline-I 以规范区间 `I*` 进行二分匹配；Proposed-C 将同一规范区间进一步分解为 Cover 节点，并在 CAP2 中增加 `matched_node` 和 `cover_version`。其余链状态、签名、Nonce、TTL 与拒绝顺序相同。

## 2. 理论支配关系

对任一允许槽 `x`，`I*` 中存在唯一极大规范区间 `I_x`，`C(P)` 中存在唯一覆盖 `x` 的节点 `D_x`。由于 Cover 节点由规范区间内部拆分得到，必有 `D_x` 的覆盖范围包含于 `I_x`。一个规范区间产生一个或多个 Cover 节点，因此，在相同上下文、TTL、容量和失效规则下，区间级缓存项可复用的槽集合不小于节点级缓存项。

Baseline-I 可以把规范区间的 `(left,right)` 绑定为 `matched_interval`，实现与 `matched_node` 相同的“命中分段可审计”能力。当前协议没有根据节点执行授权继承、委托、密钥派生、聚合更新或节点级链上状态操作，`matched_node` 仅被写入并重新验证。

## 3. 当前结论

对于当前“成员判断 + 结果缓存 + CAP2 签名”机制，未发现 `C(P)` 提供不能被同等复杂度区间机制复制的协议价值。相反，区间缓存通常以更少或相同状态覆盖不小于节点缓存的范围。节点热点工作负载若不与区间热点成对比较，会人为偏向 Proposed-C。

## 4. 决策

触发既有降级规则第 3、8 项：

```text
I*：最终语义和授权执行主表示
C(P)：可选派生结构和证伪实验对象
```

E4 可继续作为确认性证伪实验，但不得再以“预计获得层次缓存优势”作为正式主张。只有后续引入并独立论证节点级委托、聚合或密钥机制时，才能重新审查其核心地位；本阶段不引入这些新机制。
