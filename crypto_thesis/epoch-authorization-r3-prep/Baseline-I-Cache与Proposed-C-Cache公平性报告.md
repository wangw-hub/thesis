# Baseline-I-Cache 与 Proposed-C-Cache 公平性报告

## 冻结条件

B1/C1 使用同一 `LruTtlCache` 实现、容量、TTL、LRU、锁、状态上下文和失效条件。安全键均绑定链、合约、资源、策略、Epoch、资源版本、用户键、用户版本和操作；区别仅为规范区间或 Cover 节点。

## 机制结论

命中键之前，两方案都必须识别当前槽所属区间/节点。因此当前缓存不能消除策略定位步骤，只能复用定位后的判断元数据。Cover 节点包含于其来源规范区间，一个区间可能拆成多个节点，区间缓存的复用范围不小于节点缓存。

本地单元测试确认同一连续规范区间内，B1 可跨槽复用，且相同测试中区间分段大小不小于命中节点。该测试只验证实现和理论关系，不是性能预实验。

## 公平性结论

四方案接口可建立，但 Proposed-C 的缓存优势缺乏当前协议机制依据。不得将 C1 与 B0 比较后声称层次优势；正式 E4 必须以 B1 为主要强基线。
