# 研究内容二正式多主机部署设计 V1.0

## 拓扑

设计使用 VM-DO、VM-AS、VM-RM、VM-AU 四个组织 OS 实例和 VM-CLIENT。前四者各运行一个 QBFT 验证者；客户端区运行非验证 RPC、负载与监控。Issuer-1/2、Verifier-1/2 分开部署，PostgreSQL 提供共享 Nonce 与交易 Nonce 协调。

## 隔离与治理

每台主机具有独立 IP、节点密钥、数据和日志目录。ADMIN、OWNER、AUTHORIZER、REVOCATION、AUDITOR 使用不同新账户。验证节点不暴露业务 RPC。节点许可和账户角色分别测试。私钥和真实 inventory 被 Git 忽略。

## 确认语义

预注册建议 `confirmations=1`，Issuer 的两次资源/用户读取分别固定到一个确认块，签名前二次读取；Verifier 读取当前确认块。该值须在真实 QBFT 环境预实验中验证后冻结，不能沿用代码默认值。

## 交易并发

每组织使用独立发送账户；同账户多进程通过 PostgreSQL 行锁预留 Ethereum nonce。预留、广播、确认和失败状态必须持久化；已广播但回执丢失时按交易哈希查询，不盲目重发不同交易。

## 环境证据

每台主机记录 OS/VM/物理宿主关系、CPU、内存、磁盘、RTT、时钟同步、Besu/JDK/Python/Web3/PostgreSQL 版本与哈希。跨主机事件以 request_id 关联，不用墙上时间差代替端到端单调时钟。

## 当前部署状态

`infra/multihost/inventory.example.yml` 已建立，但没有真实地址或 SSH 主机。本机无可用 WSL 发行版、Hyper-V VM 集、VirtualBox/VMware 或远程 inventory。因此本设计尚未部署，不能作为多主机证据。
