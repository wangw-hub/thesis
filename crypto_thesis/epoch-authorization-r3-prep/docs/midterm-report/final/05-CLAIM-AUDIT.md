# 05 主张审计（CLAIM AUDIT）

检查类别：absolute claim、unsupported security claim、QBFT overclaim、revocation overclaim、performance overclaim。

## 修复项

1. OAuth/JWT 对比：删除“普通令牌通常只包含签发者、主体与有效期”的绝对化表述，改为“若令牌未显式绑定链标识、合约实例、策略摘要及动态状态版本，且验证时不读取共享在线状态，则令牌本身无法提供本文定义的跨部署域约束、状态版本约束与跨实例一次性消费语义”。
2. 许可联盟链术语：“公开账本”→“多方共享账本”；“确定性的公开状态”→“确定性的共享状态”；“公开事实源”→“多方共享、可验证、可审计的事实源”；“链上只保存必要的公开状态”→“共享状态”。
3. 绝对安全主张：“共同保证系统在正常路径与故障路径下都不会出现链上状态与链下执行脱节”改为“在当前冻结实现、故障模型与实验覆盖范围内，未观察到导致链上状态与链下执行不一致的违规路径”。
4. 问题排序逻辑：删除“问题一/问题三/问题二”括号回指，改为“首先理论贯通与全文结构整合，其次完善相关工作与创新边界，再根据学位论文核心论证需要开展必要的针对性补充验证，最终完成全文定稿”。
5. 学位论文 vs 阶段性论文：学位论文初稿按三项递进研究内容组织核心章节；阶段性学术论文从研究内容二或研究内容三凝练独立问题。

## 保留的边界表述（非缺陷）

- 研究内容一：层次覆盖不具普遍存储优势（负结果）；
- 研究内容二：缓存与层次覆盖无稳定端到端收益；链读取主导时延；不构成形式化安全证明；
- 研究内容三：Kubo 正常路径无稳定性能优势、恢复可用性定位；仅前瞻性撤销；单节点 QBFT 不评估多 Validator 共识性能。

UNSUPPORTED_ABSOLUTE_CLAIM = 0；FORBIDDEN_CLAIM = 0；QBFT_OVERCLAIM = 0；REVOCATION_OVERCLAIM = 0；PERFORMANCE_OVERCLAIM = 0。
