# 备份与灾难恢复

| 资产 | 可重建 | 丢失后果 | 泄露后果 | 备份边界 |
|---|---|---|---|---|
| 用户私钥 | 否 | 旧 Envelope 不可解 | 用户既得材料失守 | 用户控制、受保护导出；服务无副本 |
| ROOT_KEK | 否 | 对应 CK 永久不可恢复 | 结合 CK 密文可恢复批量 CK | 与数据库备份不同安全域；离线加密副本 |
| CAP2 私钥 | 可换但旧身份需验证 | 停止签发 | 可伪造 CAP2 | 沿用 R2 冻结流程 |
| Header 私钥 | 可换但需公钥信任更新 | 停止新 Header | 可伪造 Header | 独立加密备份，不与 ROOT_KEK 同容器 |
| 交易私钥 | 可换角色 | 停止提交 | 可执行角色权限交易 | 分账户独立备份 |
| CK 密文记录 | 否，除非已有 CK | 无法重建 Header | 单独泄露不能解 CK | 随数据库备份，完整性校验 |
| 公钥/Header/链状态 | 是 | 暂时不可用 | 非秘密 | 从签名对象和链重建 |

灾难恢复顺序：恢复干净主机与版本 → 恢复数据库密文 → 从独立安全域加载所需 ROOT_KEK 版本 → 只读完整性扫描 → 受控解包抽样 → 恢复签名/交易能力 → 对账后开放服务。任何缺失版本或 tag 失败保持 fail-closed。

论文实验不要求企业级双人控制、异地 HSM 或在线高可用 Vault；但必须记录备份位置类别、访问角色、校验摘要和恢复演练结果。不得在文档中记录真实路径或秘密。
