# KeyStore 威胁模型

| 威胁 | 设计结果 |
|---|---|
| 普通用户读取仓库 | 无秘密；不能得到 CK |
| 数据库泄露/CK记录复制 | 只得 AEAD 密文和元数据；无 ROOT_KEK 不能解 CK |
| Header复制 | Header为公开对象；签名和链锚拒绝替换，不提供 CK 明文 |
| 日志/环境变量/命令行泄露 | 禁止通过这些通道注入或记录秘密；字段级脱敏 |
| 备份泄露 | 数据库与 ROOT_KEK 分域；单域泄露不足以解 CK |
| root/完全主机失陷 | 可读取凭据目录、进程和文件；软件 KeyStore 不抵抗，ACCEPTED_LIMITATION |
| 进程内存读取 | 可能获得当前 CK/根密钥；缩短生命周期但不能声称消除 |
| ROOT_KEK 丢失 | 对应记录不可恢复；无静默降级 |
| ROOT_KEK 泄露 | 结合数据库批量暴露 CK；强制隔离、轮换和资源重加密评估 |
| 用户私钥丢失 | 服务不能恢复；登记新 userVersion |
| 用户私钥共享/泄露 | 未来撤销，既得 CK 不可追回 |
| CAP2/Header signer 泄露 | 各自域内伪造风险；独立撤销和轮换 |
| 交易密钥泄露 | 角色权限滥用；链上撤销账户并审计 |
| 数据库+ROOT_KEK 同时泄露 | CK静态保护完全失效 |

安全主张只覆盖分离泄露和最小权限边界，不覆盖恶意 root、运行时注入、供应链后门或物理主机接管。
