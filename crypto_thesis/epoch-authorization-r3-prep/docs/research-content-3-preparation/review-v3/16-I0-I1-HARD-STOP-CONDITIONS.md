# I0/I1 硬停止条件

## I0

- V13 对账未完成或发现协议接口漂移；
- 用户未明确选择 A/B/C 或未单独批准 I0；
- 需要修改 CAP2、AuthorizationState 或 R2 正式证据；
- 秘密目录位于仓库内，或必须通过环境变量/命令行注入；
- KeyStore 无法恢复 CK 或要求服务取得用户私钥；
- 依赖、许可证、版本或测试向量来源无法冻结；
- systemd 不支持目标机制且无严格权限文件的可审计降级。

## I1

- 需要正式密钥、正式链、PostgreSQL、IPFS、远程 VM 或依赖安装超出批准范围；
- RFC 9180向量失败、库并非标准HPKE或需自制原语；
- nonce唯一性、AAD绑定、完整性拒绝或签名域不闭合；
- 测试打印私钥、CK、ROOT_KEK或未分类秘密；
- 测试被用作性能结论；
- 出现无法区分的正式/测试材料。

任何停止必须保留非秘密失败证据，不允许通过放宽验证、旧Header回退或跳过用例继续。
