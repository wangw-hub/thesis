# 合并计划

本轮不 push、不合并、不 rebase。

## 前置条件

1. V13 最终审稿完成并通过 20 号对账；
2. 用户完成 KeyStore 决策；
3. 用户明确批准 R3 正式实现或批准仅合并设计文档；
4. 主仓库工作区由主任务确认可安全处理；
5. 当前分支秘密扫描为 `TRUE_SECRET=0`、`UNCLASSIFIED=0`。

## 建议流程

1. 记录主仓库目标 SHA 和 R3 分支 SHA；
2. 在不触碰 V13 原始数据的前提下审查文件级差异；
3. 如主线仅有兼容变化，采用普通 merge 或经用户批准的 cherry-pick；
4. 如存在协议接口差异，先完成 reconciliation 修订和复审；
5. 合并后只验证文档链接、JSON、Schema 和治理索引；
6. 正式实现必须在新的、明确批准的阶段提交中开始。

设计文档合并与正式实现准入是两个不同决定；前者不得隐式授权后者。
